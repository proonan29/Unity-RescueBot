# RescueBot — 재난 도시를 달리는 비전 구조 로봇 (처음부터 만드는 순서)

격자(Grid) 도시에 재난이 나서 차량·잔해·무너진 건물이 도로를 막았을 때, 캐터필러 구조 로봇이 **카메라 2D 영상만으로** 직진 / 회피 / 넘기 / 우회를 판단해 목적지까지 가는 시뮬레이터입니다.
Unity CLI + Pipeline 패키지로 Editor를 조작해 만들었습니다 (CleanerBot, WeldingBot과 같은 방식).

- 환경: Windows, Unity 6000.6.3f1 (URP), Unity CLI 1.0.0-beta.11
- 경로: `D:\UnityAIProjs\DigitalTwin\RescueBot`
- 패키지 추가: `com.unity.pipeline` 0.9.0-exp.1 (`[CliCommand]` → `unity command rb_*`)
- 작업 순서: C# 작성 → `AgentTools\build.ps1` (dryrun 컴파일 확인 → Refresh → 컴파일 대기) → `rb_*` 명령 → `snap.ps1` 스크린샷 → git 커밋
- 새 CLI 이름 주의 (pipeline 0.9): `script run`, `editor status`, `capture game_view`, `editor.playmode start|stop` (예전의 `run_script`는 없음)

## 2. 도시와 장애물

- 격자 3~9 × 3~9 블록, 블록 간격 40/60/80/100 m(기본 60), 도로 폭 12 m(차선 중심은 도로 중심에서 3 m). 교차로 주변 14 m에는 장애물을 두지 않음
- 시드가 같으면 도시가 완전히 같음 (`System.Random` 시드)
- 장애물 3등급
  - **넘을 수 있음 (Debris)**: 높이 0.35 m 이하 파편. 넘어갈 수 있지만 속도 1.6 m/s 이하, 비용 +30 m
  - **우회 (Car 1.9×4.5 m, Rubble)**: 못 넘음. 옆으로 돌아가야 함
  - **완전 차단**: 차량 3대 연쇄 추돌 또는 도로 폭 전체의 잔해 더미 → 다른 길로 재계획
- 재난 이벤트: 파편 띠 25% / 잔해 더미 37% / 차량 연쇄 추돌 38% (강도 0~100%에 따라 도로당 확률)
- **정답 판정**(`Analyze`): 도로를 0.5 m 간격으로 가로로 잘라 *장애물 사이의 가장 넓은 빈 틈*을 계산. 빈 틈 < 4.0 m(`RobotGap`)이면 Blocked, 넘을 수 있는 것까지 빼면 < 4.0 m이면 Rough. 로봇이 실제로 지나려면 폭 2.2 m + 여유가 필요해서 4.0 m로 잡음
- `EnsureReachable`: 막힌 도로 때문에 도시가 끊기면, 끊어진 곳을 이어 주는 막힘 하나를 파편 띠로 낮춤 (끄면 도달 불가 목적지도 생김)

## 3. 로봇과 카메라

- 캐터필러 로봇(길이 2.6 m, 폭 1.5 m). 운동은 결정론적 키네마틱: `dt` 0.05 s, 판단 0.2 s마다, 가속 3 / 감속 8 m/s², 최대 5 m/s, 최대 회전 1.7 rad/s, 제자리 회전 가능
- 충돌 모델: 반지름 0.9 m 원 3개(몸 앞·중·뒤) vs 장애물 상자 + 도로 가장자리 여유 0.6 m. 이미 겹친 상태에서는 *겹침이 늘어나는 이동만* 막음 (그래야 벽에 낀 채로 빠져나올 수 있음)
- **로봇 카메라**: 160×90 RenderTexture, 가로 시야각 110°, 높이 1.5 m, 아래로 22°, 로봇 중심보다 0.4 m 앞. 로봇 몸체·경로선·목적지 표시는 레이어 30에 두고 인식 카메라가 그리지 않음
- 조명은 평평한 환경광(회색 0.52)이라 도로의 채도가 낮게 유지됨. 도로 외 모든 물체의 알베도 채도 ≥ 0.2

## 4. 영상 인식 (고전 영상처리)

픽셀마다 분류:

| 분류 | 조건 (HSV) |
|---|---|
| 도로 | 채도 < 0.13, 명도 0.07~0.62 (회색) |
| 넘을 수 있음 | 색상 33~70°, 채도 > 0.55, 명도 > 0.2 (노란 파편) |
| 기타 (인도·건물·차·잔해) | 나머지 |

각 영상 열(column)을 아래에서 위로 올라가며 *연속 2행* 이상 비도로가 처음 나오는 행을 찾고, 그 행을 카메라 높이·각도로 지면에 투영해 로봇 기준 (X 오른쪽, Z 앞) 점과 종류(자유 / 넘을 수 있음 / 고체)를 얻습니다. 즉 "바로 앞 도로가 어디까지 이어지는가"를 열마다 재는 방식입니다.
`IPerception` 자리를 비워 두었으므로 나중에 CNN(ONNX / Inference Engine)으로 바꿔 비교할 수 있습니다.

## 5. 판단과 주행

**지도는 알고 장애물은 모름**: 도로망(교차로 그래프)은 로봇이 알지만 장애물은 카메라로만 알게 됩니다.

1. **전역 경로**: 교차로 그래프 Dijkstra. 비용 = 길이 + (거친 도로 +30 m), 막힌 도로는 제외. 출발지·목적지는 서로 `minBlocks` 이상 떨어진 교차로를 무작위 선택
2. **차선 폴리라인 + 목표점**: 경로를 오른쪽 차선(중심에서 3 m)의 꺾은선으로 만들고, 앞 5~9 m 지점을 목표점으로 사용
3. **지역 판단 (`Driver.Decide`)**: 카메라 점을 최근 10초 기억(0.4 m 격자로 중복 제거)과 합쳐서
   - 도로 밖(인도·풀밭) 점은 장애물이 아니라 경계로 취급 — 로봇 몸이 도로를 벗어나는 경로는 기각
   - 보이는 고체 점 뒤로 0.8 m, 1.6 m 그림자 점을 추가 (카메라는 앞면만 보므로 물체에 깊이를 줌)
   - 곡률 15개 호(최대 ±0.4) + 8개 S자(밖으로 돌았다 원래 방향으로 복귀)를 16 m까지 시뮬레이션. 6 m 이상 막힘 없이 갈 수 있는 후보만 유효
   - 비용 = 진행 − 차선 이탈 + 방향 오차 + **여유 거리 벌점(장애물에서 2.6 m 이내일수록 크게)** + 넘기 벌점 0.9
   - 결과 행동: 직진 / 좌·우 회피(이상적 곡률과 비교) / 넘기(노란 파편, 1.6 m/s) / 제자리 회전(목표가 72° 이상 옆) / 막힘
4. **막힘일 때**: 열린 방향을 찾아 *정해 놓고 끝까지* 제자리 회전(commit). 방향을 매번 다시 고르면 좌우로 계속 흔들림
5. **막힘 판정**: 막힘 상황이 30초 안에 반복될 때만(최소 2번) 해당 도로를 막힘으로 표시하고 재계획. 기억한 점으로 *도로를 가로지르는 가장 넓은 빈 틈*을 재서 2.4 m 이상이면 길이 막힌 게 아니라 판단이 서툰 것이므로 더 오래(5번) 시도. 도로 한가운데서 12초 이상 못 움직이면 마지막 막힘 위치를 표시
6. **복구**: 충돌하면 1.5초 후진, 8·16·24초 못 움직이면 2.5초 후진. 30초 동안 3 m도 못 가면 실패(stuck)
7. 아는 막힘은 한 이동(trip) 안에서만 유지. 경로 없음이면 한 번만 막힘 표시를 지우고 다시 시도

## 6. UI (UI Toolkit, 한국어/영어)

- 왼쪽: 격자 X/Y(3~9), 도로 간격, 재난 강도, 모든 교차로 도달 가능 보장, **새 Scene 생성**, **시작 / 정지**, **Loop**(도착하면 새 출발지 → 새 목적지로 반복), 속도(1/2/5/10/30×), **카메라 뷰**(전체 / 탑뷰 / 추적 / 로봇 카메라), 경로·판단 방향 표시, 범례, 언어
- 오른쪽: 로봇 카메라 영상, 영상 인식 결과(도로 / 파편 / 기타 + 방향 표시), 판단(행동·방향·앞쪽 여유·속도), 이동(구간·시간·거리·발견한 막힌 도로·경로 재계획·넘은 장애물·이상 경로 비용), 누적(성공/실패·평균 시간·효율·충돌), 최근 이동
- 로봇 카메라 뷰에서는 경로·방향선을 숨김 (화면을 가림)
- 효율 = (진실 기준 최적 경로 비용) / (실제 이동 거리 + 30 m × 넘은 파편 수). 로봇은 최적 경로를 모르므로 100%는 "처음부터 끝까지 똑바로 최적 경로로 감"

## 7. CLI 명령 (`AgentTools\rb.ps1 <명령>`, 결과만 보려면 `rbr.ps1`)

- 장면: `rb_setup_scene`, `rb_setup_font`
- 앱 제어: `rb_status`, `rb_new [--nx --ny --seed]`, `rb_advance --seconds`, `rb_set --running --loop --speed --view --lang --show_route`
- 헤드리스 평가(실제 카메라 + 인식 사용, 실시간의 약 100~150배):
  - `rb_sim_run --trips 8 --seed 1 --severity 0.5 [--nx --ny --spacing]` → 이동별 표 + 합계
  - `rb_trace --seed --trips --lines --skip` 이벤트 로그(막힘 표시가 정답과 맞는지, 충돌 원인), `--until 60 --png x` 그 시각의 카메라·인식·위에서 본 그림, `--timeline 2` 위치 기록, `--stuck true` 처음 12초 멈춘 순간, `--trip N` N번째 이동
  - `rb_city_info [--road N]` 도시 정답(막힌/거친 도로), `--road`는 도로 하나의 장애물과 폭 프로파일
- 도구: `snap.ps1 <이름> [w] [h] [camera|screen]` (UI까지 보려면 `screen`), `focus_unity.ps1`

## 9. 만들면서 얻은 교훈 (같은 실수를 피하려면)

1. **헤드리스 평가는 열려 있는 씬의 도시를 숨겨야 함.** 씬에 이미 도시가 있으면 평가용 임시 도시와 같은 좌표에 겹쳐 그려져서, 로봇 카메라에 *존재하지 않는 장애물*이 보임 → 막힘 오판·원인 모를 충돌. `Harness`가 다른 `CityView`를 숨기고 끝나면 복원
2. **눈에 보이는 모양과 충돌 상자가 같아야 함.** 잔해 더미를 조각 몇 개로만 그렸더니 충돌 상자 안에 빈틈이 보여 "지나갈 수 있다"고 판단 → 판 하나(mound)로 바닥을 꽉 채움
3. **카메라가 못 보는 곳이 있음.** 시야각 90°·앞 0.9 m 장착에서는 옆 1 m와 앞 2.5 m 이내가 안 보였음 → 110°, 앞 0.4 m, 아래 22°, 기억 10초
4. **호(arc) 후보만으로는 큰 장애물을 못 피함.** 곡률 한 가지로 16 m를 가면 원을 그리며 "길이 비어 있다"고 잘못 판단. 90°까지만 꺾고 직진(또는 S자로 복귀)하는 후보로 교체
5. **판단 단계가 서로 싸우면 영원히 제자리에서 흔들림.** "목표 쪽으로 돌기"와 "열린 쪽으로 돌기"를 번갈아 하지 말고, 한 번 정한 방향으로 끝까지 돌기
6. **감시 장치(멈춤 타이머)를 아무 때나 초기화하면 안 됨.** 효과 없는 재계획이 타이머를 계속 0으로 돌려 실패 판정이 사라짐
7. **캐터필러 로봇의 현실적 제한 속도.** 판단 주기 0.2 s에 5 m/s면 1 m를 달린 뒤에야 반응. 감속 8 m/s²로 여유 거리를 계산해 속도를 줄임
8. PowerShell로 파일을 고칠 때: 교체 쌍이 **하나뿐이면** `@( @('a','b') )`가 평평한 배열이 되어 문자 하나씩 교체하는 사고가 남. 교체 함수(`Rep 'old' 'new'`)를 쓰고, 큰 변경 전에는 git 커밋

## 10. 알려진 한계 / 다음 작업

- 로봇은 한 번에 한 가지 행동만 선택(진짜 경로 계획이 아님). 매우 좁은 틈(< 4 m)은 일부러 "막힘"으로 취급
- 카메라는 낮 시간·평평한 조명만 가정. 그림자·비·어둠·반사는 없음
- 후보: CNN(분류/세그먼트) 인식으로 교체해 고전 방식과 비교, Asset Store 차량·건물 모델, 시간이 지나며 무너지는 동적 재난, 여러 대 로봇 협업
